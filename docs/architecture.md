# Architecture

zool-theme is one React application with a thin adapter per backend. The UI never talks to Komari or
Nezha directly; it only knows the model in `src/core/model.ts`.

```
src/
  core/          model, formatting, settings, HTTP and WebSocket helpers (no backend names)
  adapters/
    komari/      /api/public, /api/nodes, /api/clients (WS), /api/records/*, /api/login
    nezha/       /api/v1/setting, /api/v1/server-group, /api/v1/ws/server (WS), /api/v1/login
    demo/        synthetic data for development and screenshots
  app/           store, router, visitor preferences, dialog state
  components/    header, footer, dialogs, chart, small UI pieces
  pages/         home and node pages
  i18n/          i18next setup and locales (en, zh-CN, zh-TW, ja)
  styles/        Tailwind v4 entry and ZOOL design tokens
public/
  os/            OS icon sprite and licence; generated by pnpm icons:os
  flags/         local 4:3 region SVG flags and licence
targets/
  komari/komari-theme.json   theme manifest and managed settings
  nezha/config.js            runtime settings shipped next to index.html
```

## Build targets

`vite --mode <target>` picks the adapter at build time through the `@adapter` alias, so each bundle
contains only its own backend code:

| Command | Output | Adapter |
| --- | --- | --- |
| `pnpm build:komari` | `dist/komari/` | `src/adapters/komari` |
| `pnpm build:nezha` | `dist/nezha/` (+ `config.js`) | `src/adapters/nezha` |
| `pnpm dev:demo` | dev server only | `src/adapters/demo` |

`pnpm package` zips both builds into `release/` together with the Komari manifest and `SHA256SUMS`.

## Data flow

1. `store.start()` loads site info and the node list, then subscribes to live updates.
2. Adapters emit `LiveEvent`s (`snapshots`, and for Nezha also `nodes`) roughly every two seconds.
3. The store keeps the latest snapshot per node and a 15-minute ring buffer used by the "Live" charts.
4. `fed` turns true with the first live frame. Before it, a node with no snapshot is *waiting*: rows
   and cards keep its identity and show skeleton bars where the readings go, the overview band shows
   dashes, and the status line says connecting. Offline is only ever what the backend reported.
5. `store.refresh()` (the header's refresh button) unsubscribes, calls the optional
   `adapter.reset()` (Nezha closes its shared socket and drops the cached frame and groups), reloads
   site and nodes, and subscribes again. The page stays mounted, so scroll, filters and the last
   snapshots stay on screen; `refreshing` ends with the first new frame or after ten seconds.
6. While the socket is down after data has arrived, the list is marked `data-stale` and its readings
   dim; they are last known values, not nodes that went offline.
7. Node pages ask the adapter for history (`loadHistory`) and latency (`loadPing`) on demand.

`MonitorAdapter.capabilities` tells the UI what a backend can do (billing, traffic quota, server-side
history, latency). Features without data are hidden rather than shown empty.

## Adding a backend

1. Create `src/adapters/<name>/index.ts` exporting a `MonitorAdapter` as default.
2. Map the backend's responses to `NodeInfo`, `Snapshot`, `HistoryPoint` and `PingData`. Keep mapping
   functions pure and exported so they can be tested against recorded fixtures in `tests/fixtures/`.
3. Add the target to `vite.config.ts` and a `build:<name>` script.

## Design tokens

Colours come from the ZOOL brand palette and are defined once as CSS variables in `src/styles/app.css`
(`--paper`, `--ink`, `--muted`, `--line`, `--wash`, `--sage`, `--sage-text`, plus `--surface`, `--good`,
`--warn`, `--warn-fill`, `--danger` and chart colours). Tailwind utilities such as `bg-paper` or `text-muted` map to them, and
`[data-theme=dark]` swaps the values. Only the resolved theme is stored on `<html>`; the visitor's choice
lives in `localStorage.appearance`, a key shared with other Komari themes.

## Privacy and performance

- No third-party requests. Inter is bundled; there is no analytics or exchange-rate lookup.
- Asset names are content-hashed, so CDNs can cache `assets/` for a long time.
- Komari polling pauses while the tab is hidden (Nezha pushes frames from the server); WebSockets reconnect with capped backoff.
